## Limits that stay visible

- The lifecycle lock serializes cooperating gripsack processes for one
  home. It excludes neither editors nor arbitrary external writers.
- A pinned parent capability prevents pathname-redirection races; it is
  not an atomic compare-and-swap of bytes/mode against all writers. The
  observation-to-write window is documented on the safety page.
- Hash equality assumes SHA-256 collision resistance for content
  identity; encoding injectivity (RECOVERY-IDENTITY-001) is separate
  and does not depend on it.
- Process-crash tests and power-loss models are different evidence:
  kernel caches surviving `kill -9` say nothing about physical storage
  failure; the TLA+/explorer power-loss lanes cover the reordering
  envelope, not the hardware.
- File/directory sync and rename semantics are trusted OS/filesystem
  contracts, qualified to the platforms CI exercises.
- The current-pointer switch is a logical generation commit; outside
  readers do not receive an atomic multi-file snapshot.
- Activation hooks can be replayed after a crash; neither
  exactly-once effects nor eventual hook success are promised.
- Verified or not, policy functions do not prove Deno, TLS, the
  compiler, the solver or storage hardware.

The general safety model contains no crash counter. Its destination domain
may be empty; transaction identities range over a nonempty finite universe,
with arbitrary permitted per-transaction intent counts and attempt bounds.
Proofs quantify those parameters rather than lifting a TLC state count into
a universal claim. Finite discovery cfgs choose explicit smaller domains.

`RepeatedRecovery` and `RepeatedActivation` are separate conditional
completion explorers. Their finite crash budgets, finite work, successful
scheduled I/O and fairness assumptions are not production retry limits.
The old hard-coded `MultiDestination` transition engine is removed.

The joined cooperating-core model excludes outside writes to private
control metadata. The standalone journal model additionally covers admitted
unexpected selections and refusal; malformed-byte admission is exercised by
the actual decoder/recovery campaign. External destination edits are modeled
as durable edits under the existing ownership contract, without a portable
compare-and-swap claim. Process death retains kernel-visible state; modeled
power loss resolves independently dirty fields. Neither is certification of
physical filesystem or device behavior.


## Journal proof-to-effect boundary

`journal_protocol` proves the publication acknowledgement sequence, role-bound
mutation admission, exact cleanup progress and terminal refusal. The production
storage and recovery drivers consult those states before effects and acknowledge
the actual result afterward. The owned `JournalRun`, `CapturedPrior`,
`MutationPermit` and `CommittedSelection` constrain the real executor; no older
directory-only mutation or commit adapter remains.

The external storage contract is explicit: syncing the staged file seals the
written bytes/mode; same-directory rename publishes that file atomically;
syncing its pinned parent seals the name. Destination observation comes from
the captured parent capability and same file handle where applicable. Capture
is not compare-and-swap against concurrent external writers. The lifecycle
session excludes other cooperating core writers, not arbitrary same-UID changes
to private runtime state.

Neither a Verus acknowledgement nor a Rust IO receipt proves the filesystem
honored those operations. Actual publication traces, source-level dropped-sync
mutants, real recovery/persistence campaigns and native runs check the mapping.
They are not a formal model-to-Rust refinement theorem or hardware power-loss
certification. The development proof and real CLI journey are retained in
[`2026-09-29-m-v7-journal-development.log`](reports/2026-09-29-m-v7-journal-development.log);
complete local proof/effect calibration and the 417-case CLI gate subsequently
passed, retained in the [integrated gate receipts](reports/README.md#integrated-m-v6m-v7--complete-local-gates-at-the-8143443-checkpoint).
Exact-candidate/native qualification remains open.

## Native process observation boundary

An owned `Child` is consumed by the lifecycle guard before its pipe handles are
transferred to the exchange. The checked state machine governs observe, signal
and reap admission; the OS still supplies the actual outcomes. Cleanup preserves
the first failure and its native errno even when the leader can be reaped later.
No concurrent external reaper, PID-forging caller or complete escaped-descendant
tree is admitted by this contract.

Darwin's [`killpg1`](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c)
filters zombies before selecting signal recipients; EPERM therefore cannot
by itself distinguish a zombie-only group from denied live processes.
The exceptional observation uses
[`proc_listpids`](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c)
membership snapshots and the documented
[`libproc` PID-count API](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c).
Both snapshots must be complete and retain the unreaped group leader.
Only previously observed dead PID/birth identities may remain; new, live,
changed, truncated, unreadable or expired observations preserve the signal
failure. Kernel membership completeness, birth-identity fidelity and zombie
state semantics are explicit external assumptions, not Verus postconditions.
Native macOS qualification of this new observer remains pending.
