# 0035 - Review response: the fb11aaf (0.31.0) external review

Status: **implemented in 0.32.0** (fixes), roadmap for the deferred.
Source: a third external review — against the shared-op architecture.
Every reproduced claim re-verified against the tree before acting.

## Adopted, fixed in this release

| # | Finding | Fix |
|---|---|---|
| F1 | Spelling change deletes a still-declared file (prune compares raw strings; deploy looks up canonically) | The manifest records the CANONICAL destination key plus the declared spelling; prune, rollback, why-owns, and prior inheritance all key canonically. Op harness case: spelling change mid-epoch moves nothing. |
| F2 | Failed verifier bypassed on retry (store presence skips verify) | Presence is not a receipt. Verification runs on every apply over the staged artifact; a failed run leaves nothing trusted. |
| F3 | A typo'd field (`confg:`) passes check, then prunes | `module()` rejects unknown fields at eval with a span-accurate error before lowering. Runtime validation, not just editor types. |
| F4 | Build-dep pin update leaves the consumer's cached output stale | `module_input` incorporates the dependency's RESOLVED identity (lock pin/tree), not just its declaration. |
| F5 | Activation-record write failure escapes compensation (0032's own hole) | Every fallible op between first mutation and flip compensates: the pending write joins the transaction body. |
| F6 | `cargo install gripsack` ships no frontend (build.rs reads outside the crate) | The frontend table is a generated Rust source vendored INTO the crate (`embedded_frontend.rs`, regenerated by a script, freshness-checked in CI); crates.io builds carry the full frontend. Packaged-install smoke test in the release gate. |
| F7 | Preview side effects + misclassification: plan creates parent dirs; satisfied owned link reads as new; deferred dest shows as pruned | Preview observes read-only (no capability create); owned-link preview resolves the offline store path; deferred ops count as declared for pruning. |
| F8 | Explicit steps: configStep's repo source never reaches the payload; cross-phase needs unsupported-but-accepted | Overlay/identity collection walks the EXPANDED step graph (one normalized graph). Needs on deploy-phase products are rejected at check with a pointer to activation hooks (post-deploy semantics belong there). |
| F9 | `on_remove` hook fires at install and never at removal (trigger dropped at expansion) | Triggers survive into the step IR; activation runs post_link/post_activate only; removal intents fire from the previous generation's manifest (which now records intents). |
| F10 | `[eval.env]` can override GRIPSACK_DENO — repo build vars redefine operator runtime policy | `eval.env` never touches process-global env; it passes to the build-step subprocess only. `GRIPSACK_*` is a reserved namespace there. |
| F11 | Same-filesystem publish renames without syncing staged contents | Publish fsyncs the staged tree (files + dirs) recursively before the rename — the same durability the copy path had. |

## Modeling notes

- The spelling-identity bug (F1) is the aliasing class the lineage
  explorer already models at declaration level — the op harness now
  covers the manifest/spelling case end to end.
- The normalized-graph consolidation (F8) keeps the rule: TLA+ for
  protocols (transaction, activation), the Rust harness for decision
  functions, the op harness for the lifting. Expansion/lowering joins
  the op harness's coverage.
- No new spec: the transaction boundary fix (F5) is a coverage bug in
  the caller — Transaction.tla's oracle ("compensate or commit")
  already states the rule it violated, and `specs/Activation.tla`
  covers the record's lifecycle. The e2e fault test (activation record
  path replaced by a directory) is the boundary proof.
