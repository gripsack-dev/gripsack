## Current-writer and ergonomic design

New declaration authority uses **IR8**. Strict v7/v6/v5 execution retains its
original meanings; v4/v3 historical contracts are not reinterpreted. The0.47
reviewer prerelease is published;0.48 is the next candidate, with coordinated
component versions and measured helper pins. No existing release bytes change.

- `templateFile(variables, resultDigest?)` renders its orthogonal captured file
  source. Identity includes source bytes, normalized executable classification,
  transform, variables and digest claim. This is not arbitrary permission-bit,
  owner, setuid or ACL preservation.
- `repoTree(path, { include?, exclude? })` selects normalized segment-prefix
  paths, not globs. Core expands approved captured inventory. Internal aliases
  retain logical destinations backed by confined regular sources; directory
  cycles, escapes, unavailable targets and expansion-budget violations refuse.
  Declaration filters and source-capture exclusions remain distinct: filtering
  cannot retroactively approve an outbound link rejected during capture.
  Current SDK `treeFiles` is replaced, not kept as a second walker or shim.
- `archiveRoot: { kind: "single_directory" }` selects exactly one real payload
  directory. Root files/metadata siblings, ambiguous roots and aliases refuse;
  nothing is silently skipped. Commands and artifact file/tree selection share
  the same receipt-bound root. Existing string selectors remain literal.
- `profile(..., { environment, launchers: { directory, commands }, files })`
  installs only explicit, uniquely resolved commands. Core owns executable
  launchers and activation bindings, uses an absolute retained core path and
  re-admits packages/runtime on each launch. It never finds `grip` via PATH or
  recursively executes the public launcher name. Missing core/runtime authority
  fails with supported reapply/recovery guidance.

The intended result is one recognizable profile/file model, not a parallel
high-level configuration language. A small actual consumer journey must replace
its duplicated template, generated tree manifest/traversal and handwritten
launchers with these declarations. Keep one consumer integration test; move
traversal/safety contracts into Gripsack.

## Lifecycle acceptance

Legacy migration is explicit and generation-bound, not an expansion of
`--take-over`. Replacement packages/runtime/content are prepared before old
paths disappear. Existing lifecycle locks and journal operations own predecessor
re-observation, ownership transitions, compensation and publication. A directory
replacement must never write through an old symlink. Foreign/drifted paths are
preserved or refused, and prior lineage/rollback closure remains retained.
Precommit checks may block cutover; postactivation hook/verification failure
must retain explicit recovery, not add forbidden automatic rollback.

Repeat apply must first recover unfinished work and admit complete state.
Comparing only store paths or selected JSON fields cannot establish no-op.
Repairs remain observable and recoverable; any independent apply-event identity
must retain its activation/journal/GC roots. The original semantic-change epic's
unknown-not-equal and stale-binding restrictions remain mandatory.
